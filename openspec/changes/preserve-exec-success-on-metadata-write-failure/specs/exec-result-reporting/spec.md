# Spec Delta

## Purpose

Определить, как env-vault сообщает результат выполненного child-процесса и
обрабатывает отказ записи его метаданных, сохраняя различие между результатом
команды, ошибками потоков и безопасностью выходного файла.

## ADDED Requirements

### Requirement: Успех child сохраняется при отказе файла метаданных

После реального выполнения child с кодом `0`, без ошибок запуска, ожидания и
передачи потоков, env-vault SHALL сохранять код `0`, если единственная ошибка —
отказ публикации `--output`. Этот отказ сам по себе SHALL NOT вызывать
повторный запуск child или повторную попытку публикации.

#### Scenario: Успех с доступным выходным файлом

- **WHEN** child завершается с `0`, а `--output` указывает на отдельный доступный обычный файл или новый путь
- **THEN** env-vault возвращает `0` и публикует прежний success envelope с `ok: true`, `command: "exec"`, `error: null`

#### Scenario: Выходной путь оказался каталогом

- **WHEN** child завершается с `0`, `--output` указывает на существующий каталог и других ошибок нет
- **THEN** env-vault возвращает `0`, каталог сохраняется и child был запущен ровно один раз

#### Scenario: Отказ публикации без повторов

- **WHEN** после успеха child публикация метаданных завершается отказом и успешный вывод в stdout не встречает ошибок
- **THEN** env-vault не начинает повторную публикацию успешного envelope, не заменяет его error envelope и не запускает child снова; ограниченные повторы существующего механизма файловой записи сохраняются

### Requirement: Диагностика отказа файла включается явно

Отказ `--output` после успешного child SHALL добавлять в stderr одно
диагностическое сообщение с префиксом `OUTPUT_WRITE_FAILED:` только при
`--verbose`. `--quiet` SHALL NOT подавлять запрошенную verbose-диагностику.
Собственные stdout/stderr child SHALL сохраняться.

#### Scenario: Обычный и quiet-режимы без verbose

- **WHEN** child пишет публичные маркеры в stdout/stderr, завершается с `0`, запись файла отказывает, а `--verbose` отсутствует
- **THEN** в human-режиме с `--quiet` и без него потоки содержат только маркеры child, без `RUNTIME_ERROR` и `OUTPUT_WRITE_FAILED`

#### Scenario: Verbose с quiet и без него

- **WHEN** тот же child выполняется с `--verbose`, включая сочетание с `--quiet`
- **THEN** после stderr child добавляется одно сообщение `OUTPUT_WRITE_FAILED: …`, stdout child не меняется и код завершения остаётся `0`

### Requirement: Машинный вывод успеха не зависит от публикации файла

Для успешно выполненного child env-vault SHALL продолжать прежний вывод
success envelope в stdout при `--json` или `--jsonl`, даже если запись
`--output` отказала. Формат и поля SHALL сохраняться: отказ файла не добавляет
`exit_code: 0`, элемент в `warnings` или объект `error`.

#### Scenario: JSON и JSONL после отказа файла

- **WHEN** молчащий child завершается с `0`, файл недоступен, включён один из `--json`/`--jsonl`, с `--quiet` или без него
- **THEN** stdout содержит один успешный envelope команды `exec` с прежними данными, непустым timestamp, `warnings: []` и `error: null`; код — `0`

#### Scenario: Машинный вывод вместе с потоками child

- **WHEN** child пишет публичный маркер и завершается с `0`, включён `--json` или `--jsonl`, а файл метаданных недоступен
- **THEN** stdout сохраняет маркер child и следующий за ним success envelope, как при доступном файле; `--verbose` влияет только на дополнительную диагностику stderr

### Requirement: Защита выходного пути сохраняется до и после child

env-vault SHALL сохранять предварительную проверку `--output` и проверку
перед публикацией. Конфликт, найденный до запуска, SHALL блокировать child.
Конфликт, возникший после успешного child, SHALL предотвращать запись по этому
пути и обрабатываться как отказ файла, сохраняя результат child.

#### Scenario: Конфликт с конфигурацией обнаружен до запуска

- **WHEN** `--output` совпадает с явной конфигурацией, её lock-файлом или распознанным файловым алиасом конфигурации до запуска
- **THEN** env-vault возвращает `USAGE` с кодом `2`, child не запускается и защищённые файлы не меняются

#### Scenario: Алиас конфигурации появляется во время выполнения

- **WHEN** начальная проверка прошла, child создаёт hard-link алиас временной конфигурации на пути `--output` и успешно завершается
- **THEN** повторная проверка отказывает в публикации, конфигурация и созданный алиас не заменяются; код — `0`, а `OUTPUT_WRITE_FAILED` появляется только с `--verbose`

### Requirement: Неуспешный child сохраняет свой результат

Для ненулевого кода child или его завершения сигналом env-vault SHALL
сохранять действующее поведение: child status и платформенную обработку
сигнала, `COMMAND_FAILED` в доступном файле метаданных, диагностику отказа
этого файла только с `--verbose`.

#### Scenario: Ненулевой код

- **WHEN** child завершается с `7`, независимо от доступности отдельного пути `--output`
- **THEN** env-vault возвращает `7`, сохраняет потоки child и при доступном файле записывает `COMMAND_FAILED` с `data.exit_code: 7`

#### Scenario: Завершение сигналом на Unix

- **WHEN** child завершается от SIGTERM при обычных условиях Unix без PID 1 и других специальных режимов
- **THEN** env-vault сохраняет существующее завершение тем же сигналом независимо от отказа `--output`; доступный файл содержит `COMMAND_FAILED`, `data.exit_code: 143` и `data.signal: "SIGTERM"`

### Requirement: Ошибки вне публикации успешного exec остаются ошибками

env-vault SHALL сохранять строгую обработку ошибок метаданных для других
команд и `exec --dry-run`. Ошибки запуска, ожидания, копирования потоков child
и записи собственного stdout SHALL NOT преобразовываться в успех этим
правилом обработки файла.

#### Scenario: Version и dry-run с недоступным файлом

- **WHEN** `version` или корректный `exec --dry-run` используется с `--output` на существующий каталог
- **THEN** env-vault возвращает `RUNTIME_ERROR` с кодом `1`; в dry-run child не запускается

#### Scenario: Исполняемый файл отсутствует

- **WHEN** указанный child executable отсутствует, а `--output` недоступен
- **THEN** env-vault сохраняет `COMMAND_NOT_FOUND` и код `127`, не объявляя выполнение успешным

#### Scenario: Ошибка собственного stdout после молчащего child

- **WHEN** молчащий child завершается с `0`, но последующая запись success envelope в stdout для `--json` или `--jsonl` возвращает ошибку
- **THEN** сохраняется существующая обработка `RUNTIME_ERROR` с кодом `1`; ошибка stdout не маскируется как нефатальный отказ `--output`
