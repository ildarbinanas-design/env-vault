# Proposal

## Why

После успешно выполненного child-процесса `exec` может вернуть `1` вместо `0`,
если не удалось записать `--output`: автоматизация получает ложный отказ и может
повторить уже выполненное действие. Сохранение результата child устраняет
конкретный риск для владельца в границах
[ADR 0013](../../../docs/adr/0013-owner-benefit-scope.md).

## What Changes

- После реального успешного выполнения child отказ публикации `--output`
  не меняет код завершения `0`; `OUTPUT_WRITE_FAILED` выводится только с
  `--verbose`, по образцу уже существующего поведения неуспешного child.
- После отказа файла продолжается обычный успешный human/JSON/JSONL-вывод;
  поля JSON и поведение `--quiet` сохраняются.
- Предварительные проверки пути и повторная проверка перед публикацией
  сохраняются: ошибка не разрешает записывать поверх защищённых данных.
- Добавляются переносимые регрессионные сценарии и описание границы между
  результатом child и отказом записи метаданных.

Изменение кода `1 → 0` относится только к отказу файла после успешного runner.
Ошибки запуска, ожидания, копирования потоков и записи stdout, ненулевые статусы,
сигналы, другие команды и `exec --dry-run` сохраняют нынешний контракт.
Новых команд, флагов или полей вывода нет.

## Capabilities

### New Capabilities

- `exec-result-reporting`: результат выполненного child и его отражение в
  метаданных, включая отказ публикации после успешного выполнения.

### Modified Capabilities

Нет: инвентарь основных OpenSpec-спецификаций пуст. Это первая формализация
узкой части существующего `exec`, поэтому delta использует `ADDED Requirements`.

## Impact

Будущая реализация затрагивает `internal/cli`, `internal/output`, их тесты и
сценарий E2E `OUTPUT_JSON_JSONL_FILE`; документация —
[README](../../../README.md#output-and-dry-run) и
[дизайн вывода](../../../docs/design.md#output-schema).
Runner, backend, атомарная запись, зависимости и release-процесс не меняются.

**Подтверждённые факты.** На чистом `main` (`b6ff33a`) проверены
[успешная ветка CLI](../../../internal/cli/cli.go),
[Success и CommandFailed](../../../internal/output/output.go) и безопасное
воспроизведение без mappings с полностью включённым test backend:
child `0` + `--output` на каталог дают CLI `1`; child `7` дают CLI `7`.
Тестовое хранилище при воспроизведении не создавалось. Подробности проверки —
в [design.md](design.md).

**Согласованное решение.** Владелец выбрал сохранение кода child и диагностику
только с `--verbose`. Артефакты этого изменения готовятся для review;
реализация начинается отдельным этапом после него.

**Предположения и вопросы.** Минимальное решение ограничивается рендерером и
его вызовом в CLI; карта проверок находится в [tasks.md](tasks.md).
Продуктовых вопросов не осталось. Native Linux/Windows ещё не проверены.

Также рассматривались полезные подсказки в `doctor` и изолированная проверка
восстановления macOS Keychain. Первый вариант требует отдельного контракта
предупреждений, второй — интерактивной тестовой сессии. Открытый
[P0](../../../backlog.md#p0) этим изменением не закрывается.
